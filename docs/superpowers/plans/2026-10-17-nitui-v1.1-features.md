# nitui v1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox syntax.

**Goal:** Live server status, settings editing, update notifications, game management, backups, file manager, console/logs, JSON output, `--server` flag, confirm prompts.

**Architecture:** New API endpoint groups as methods on `api.Client` in new files; CLI one file per command group; TUI split into per-screen files sharing a confirm modal.

**Tech Stack:** Go 1.25, cobra, bubbletea/bubbles/lipgloss, yaml.v3, httptest for tests.

**Spec:** `docs/superpowers/specs/2026-10-17-nitui-v1.1-features-design.md`

## Global Constraints

- Module path `nitui`; no new third-party dependencies unless unavoidable.
- Tests: `go test ./...` must pass after every task; also `gofmt -l .` empty and `go vet ./...` clean.
- Unverified API shapes must fail gracefully, never panic.
- Tests never touch the network or the real profile (`NITUI_CONFIG_DIR`, `apiBaseURL`).
- Existing behavior of current commands stays compatible (output text of existing commands may only be extended).

## Tasks (each ends with `go test ./...` green)

### Task 1: Foundation
Files: `internal/cli/server_flag.go` (new), `internal/cli/output.go` (new), `internal/cli/confirm.go` (new), `internal/cli/root.go`, `server.go`, `servers.go`, `games.go`, `internal/api/types.go`.
- Produces: `resolveServer(cmd *cobra.Command) (int, error)` (honors persistent `--server`, else state); `wantJSON(cmd) bool` + `printJSON(cmd, v any) error`; `confirm(cmd, prompt string, yes bool) (bool, error)`; persistent flags `--server int`, `--json bool`.
- Types: `GameServer` gains `Settings map[string]map[string]any`, `UpdateStatus string` (from `game_specific.update_status`), `Memory`, `MemoryMB`, `Username`, `Label`.

### Task 2: Live status (api + CLI + TUI)
Files: `internal/api/wait.go`+test, `internal/cli/server.go`, `internal/tui/{model,update,view,commands}.go`.
- Produces: `api.WaitForStatus(ctx, fetch, WaitOptions) (*GameServer, error)`, `api.TimeoutError`; CLI `--wait`, `--watch`, `--message`, `--yes`; TUI wait tick + passive refresh + confirm modal for stop/restart.

### Task 3: Update notification
Files: `internal/update/{update,cache}.go`+tests, `internal/config/config.go` (`UpdateCheck *bool`), `internal/cli/root.go` (post-run note), `internal/tui` (banner msg).
- Produces: `update.Check(ctx, current string, opts) (*Release, error)`, `update.IsNewer(current, latest string) bool`.

### Task 4: Settings
Files: `internal/api/settings.go`+test, `internal/cli/settings.go`+test, `internal/tui/screen_settings.go`+test.

### Task 5: Game management
Files: `internal/cli/games.go` (start/uninstall), `internal/tui` picker keys, tests. Installed games use `StartGame`.

### Task 6: Backups
Files: `internal/api/backups.go`+test, `internal/cli/backups.go`+test, `internal/tui/screen_backups.go`.

### Task 7: File manager
Files: `internal/api/files.go`+test, `internal/cli/files.go`+test, `internal/tui/screen_files.go`.

### Task 8: Console & logs
Files: `internal/api/console.go`+test, `internal/cli/console.go`, `internal/tui/screen_console.go`.

### Task 9: Update spike + stats + richer detail
Files: `internal/api/stats.go`, `internal/cli/server.go` (`update`, `stats`), `internal/tui/view.go` detail.

### Task 10: Docs
README commands/Known gaps, example config (`update_check`).
